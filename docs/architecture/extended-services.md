# Extended service coverage

CloudSentry scans eight services beyond the original EC2/EBS/EIP/RDS/snapshot/NAT/ELB set: Lambda, EKS, ElastiCache,
CloudFront, EFS, DynamoDB, Redshift and AWS Backup. This document is the contract between discovery
(`services/scanner`), detection (`services/analyzer`) and pricing/savings (`services/recommendation`).
Types live in `packages/shared-types/src/{resources,metrics,pricing,enums}.ts`; customer permissions in
`packages/shared-types/src/permissions.ts` (all read-only).

General rules (unchanged): missing metrics are `NO_DATA`, never zero, and rules return `NOT_EVALUATED` instead of
guessing; every rule honours the ignore tag; savings come only from AWS Price List prices; when savings cannot be
priced honestly the rule emits `savingsRequest: null` (or the savings engine returns `UNAVAILABLE` with a reason).

## 6. Workflow

Each new type has its own discovery Lambda and Parallel branch (`services/scanner/src/handlers/discover-<name>.ts`):
`lambda-functions`, `eks-clusters`, `elasticache-clusters`, `cloudfront-distributions`, `efs-file-systems`,
`dynamodb-tables`, `redshift-clusters`, `backup-plans`, `backup-vaults`.

Existing customer roles created before this change lack the new permissions. Discovery of those types then fails
with AccessDenied per region; scans complete as PARTIALLY_COMPLETED with clear errors, and verification shows the
new permissions as DENIED until the CloudFormation stack is updated with the new template.
